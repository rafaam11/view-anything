# COPC와 LAS 파형 지원 조사

2026-10-28 기준. 이 문서는 구현 범위를 확정하기 위한 조사이며 현재 앱은 두 형식을 보존 저장할 수 없어 거부한다.

## COPC

[COPC 1.0 명세](https://copc.io/)는 COPC를 LAZ 1.4에 옥트리 계층과 청크 위치를 더한 형식으로 정의하며 점 레코드 형식 6·7·8을 사용한다. 계층 항목에는 데이터 청크와 하위 계층 페이지의 파일 오프셋과 길이가 들어 있다. 따라서 필터나 정합 후 원래 VLR/EVLR을 그대로 복사하는 것은 유효한 COPC 저장 방법이 아니다.

- **읽기 후보**: 계층의 범위·오프셋·길이를 검증한 뒤 필요한 LAZ 청크를 읽고 기존 청크 표시와 취소에 연결한다. 1천만 점·세션 메모리 한도는 유지한다.
- **저장 후보**: 선택 결과의 옥트리·청크 테이블·계층 페이지와 관련 메타데이터를 새로 만들고 독립 구현으로 재검증한다. 단순 LAZ 변환은 사용자가 명시적으로 선택하는 별도 기능이어야 한다.
- **검증 과제**: 큰 계층, 빈 노드, 손상·순환 참조, 범위 밖 오프셋, CRS·추가 바이트 보존, 취소·저장 실패 및 독립 리더 재열기를 시험한다.

## LAS 파형

[ASPRS LAS 명세](https://lasformat.org/latest/02.00_definition.html)의 파형 점 레코드는 파형 패킷 설명자, 크기와 데이터 오프셋을 참조한다. 파형 데이터는 LAS의 확장 레코드 또는 별도 WDP 파일에 있을 수 있다. 점 레코드만 다시 쓰면 참조가 깨질 수 있으므로 현재 거부 정책을 유지한다.

- **읽기 후보**: 내부·외부 파형의 참조 범위와 설명자를 검증하고 외부 파일 누락을 명확히 표시한다. 외부 파일 접근은 사용자가 선택한 원본과 명시적으로 연결된 파일로 제한한다.
- **저장 후보**: 선택한 점이 참조하는 패킷과 설명자를 보존하고 새 파일의 오프셋을 재계산한다. 외부 WDP가 필요하면 여러 파일을 함께 안전하게 확정하는 절차가 필요하다.
- **검증 과제**: 공유 패킷, 빈 참조, 손상 오프셋, 외부 파일 누락, 취소·중간 실패와 독립 리더의 파형 바이트 대조를 포함한다.

## 다음 단계 제안

두 형식 모두 우선 읽기 전용 프로토타입과 공개·합성 샘플 검증을 수행한다. 쓰기 기능은 재구성·원본 보존·다중 파일 원자성에 대한 별도 설계와 사용자 승인 후 계획한다. 현재 `vendor/las`의 패닉 방지 패치와 라이선스도 새 구현을 선정할 때 함께 검토한다.
