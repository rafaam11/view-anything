# v0.14.0 — 1천만 점 LAS와 분류 색상

포인트클라우드가 문서의 약속대로 동작하도록 한도와 색상을 바로잡고, LAS 분류 색상 모드를 추가했습니다. 일반적인 LiDAR 타일 크기의 LAS/LAZ를 열 수 있고, 한도를 넘는 파일은 읽기 전에 거부하며, 큰 점군을 더 빨리 화면에 올립니다.

- **LAS/LAZ 점 수 한도**: 예전에는 작업 메모리 추정치를 2GiB 디코딩 한도와 비교해 약 450만 점부터 거부했습니다. 이제 표시 레코드는 2GiB, 작업 메모리는 8GiB 앱 예산과 따로 비교해 장면 합계 1천만 점까지 엽니다. 사전 추정치는 열린 세션의 실제 메모리 계산과 같습니다.
- **분류 색상 모드**: 색상의 "분류"를 고르면 ASPRS 분류(0~22)별 색으로 칠하고 패널에 범례를 표시합니다. 모든 LAS/LAZ와 `classification` 필드가 있는 PCD/PLY에서 쓸 수 있으며, HTML로 내보내면 보이는 색 그대로 담깁니다.
- **8비트 LAS 색상**: 16비트 색 필드에 0~255 값을 담은 LAS가 거의 검게 보이던 문제를 고쳤습니다. 파일 전체에서 255를 넘는 값이 없으면 8비트로 표시하며 저장되는 원본 값은 바꾸지 않습니다.
- **PCD 헤더 보존**: 저장할 때마다 `# .PCD v0.7` 줄이 하나씩 늘어나던 문제를 고쳤습니다. 사용자 주석은 그대로 유지합니다.
- **한도 선검사**: 장면 합계 1천만 점이나 메모리 한도를 넘는 파일은 헤더의 점 수로 판단해 본문을 읽기 전에 거부합니다.
- **큰 점군 로딩 속도**: 25,000점 청크마다 한 프레임씩 기다리던 GPU 업로드를 12ms 시간 예산마다 양보하도록 바꿨습니다. 1천만 점에서 최소 400프레임(약 6.7초)이던 대기 하한이 사라졌고, 창을 최소화해도 로딩이 멈추지 않습니다.
- **번들 예산 검사**: `check:bundle`이 진입 청크 60KiB, Markdown 뷰어 청크 800KiB 예산과 PDF·이미지·텍스트·데이터 뷰어 청크의 3D 정적 참조를 함께 검사합니다(현재 38KiB, 708KiB).
- **CI**: Rust 툴체인을 1.99.0으로 고정해 새 stable의 clippy 규칙이 예고 없이 main을 깨지 않게 했습니다.
- **로컬 검증**: JavaScript 705개 통과·2개 건너뜀, Rust 62개 통과와 타입 검사·빌드·번들 검사·clippy(1.99.0)를 확인했습니다.
- **한계**: 1천만 점 LAS는 예산 계산과 합성 파일 단위 테스트로 검증했고 실제 파일의 로딩 시간·메모리 실측은 하지 않았습니다. 구형 LAS 형식(0~5)의 겹침 점은 라이브러리가 분류 1로 읽어 "12 예약(겹침)" 색으로 칠해지지 않습니다. ICP 점대면 정합, COPC, LAS 추가 속성 표시는 후속 범위입니다.
