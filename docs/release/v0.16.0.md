# v0.16.0 — Windows 11 방식으로 맞춘 버튼·대화상자·알림

뷰어마다 달랐던 버튼, 확인창, 알림, 찾기, 메뉴를 하나의 모양과 동작으로 맞췄습니다. 업데이트 재시작 창을 포함한 모든 확인은 앱 안의 같은 대화상자로 묻고, 저장 같은 완료 알림은 화면 아래에 잠깐 보였다가 사라집니다.

- **버튼과 입력칸**: 모든 버튼·입력칸이 같은 모양을 씁니다. 보조 버튼은 옅은 채움, 주 버튼은 강조색, 위험한 동작은 빨강이며 모서리와 높이, 포커스 표시가 같습니다. 체크박스와 슬라이더도 앱 강조색을 따르고, 업데이트 재시작 창의 브라우저 기본 버튼이 사라졌습니다.
- **앱 대화상자**: 버리기 · 교체 · 경고 · 오류를 OS 대화상자 대신 앱 안에서 묻습니다. 버튼은 실행할 일을 이름으로 쓰고(버리기 · 닫기 · 다시 읽기 · 교체), 안전한 쪽에 포커스가 있어 Enter나 Esc로 실수하지 않습니다. 대화상자가 열린 동안 다른 단축키는 동작하지 않습니다. 설정과 PDF 암호 창도 같은 모양입니다.
- **완료 알림**: 저장 · 복사본 저장 · 이미지와 경로 복사 · PNG 저장 · HTML 내보내기가 끝나면 화면 아래에 짧게 알립니다. Markdown 저장도 알립니다. 3D에서 PNG 저장 성공이 빨간 오류 배너로 보이던 문제를 고쳤습니다.
- **문구 통일**: 저장하지 않은 변경, 외부 변경 충돌, 오류 문구를 모든 뷰어에서 같게 씁니다. 파일이 바깥에서 바뀌어 저장하지 않았을 때는 편집 내용이 그대로 있다는 경고로 알리고, 오류에는 "Error:" 접두어를 붙이지 않습니다.
- **3D 배너**: 안내 · 경고 · 오류를 색과 읽기 방식으로 구분합니다. 불러오는 중 내보내기 거절 같은 안내는 더 이상 오류처럼 보이지 않습니다.
- **찾기 막대**: Markdown · PDF · 텍스트가 같은 찾기 막대를 씁니다. Enter와 Shift+Enter로 이동하고 Esc로 닫으며, 결과 수가 막대 안에 보입니다. PDF와 텍스트에서 한글 조합을 끝내는 Enter가 검색을 실행하던 문제를 고쳤습니다.
- **파일 메뉴**: 모든 뷰어의 파일 메뉴가 열기… · 텍스트로 열기… · 최근 파일 · 뷰어별 명령 순서입니다. 3D에도 텍스트로 열기…가 생겼고, 업데이트 확인은 오른쪽 아래 업데이트 메뉴(`Ctrl+Shift+U`)로 모았습니다. 단축키는 메뉴 오른쪽에 표시합니다.
- **화면 다듬기**: 빈 창에 열기… 버튼을 두었고, 열 수 없는 파일 화면은 이유와 "이 파일을 텍스트로 열기"를 보여 줍니다. CSV 페이지 이동은 아이콘 버튼, 이미지 자르기는 [자르기 적용][취소]입니다. 긴 최근 파일 이름은 메뉴 폭을 늘리지 않고 말줄임으로 줄입니다.
- **함께 고친 문제**: 업데이트를 맡은 창이 최소화돼 있으면 재시작 확인이 보이지 않아 모든 창이 잠긴 채 남던 문제를 고쳤습니다. 내보낸 HTML의 메뉴가 앱 메뉴 스타일을 받지 못하던 문제도 고쳤습니다.
- **눈에 보이는 변화**: Markdown 링크와 목차 강조색이 Windows 강조색으로 조금 바뀌었습니다. 컨트롤 위 마우스 커서는 Windows처럼 기본 화살표이고, 아이콘 버튼은 28px, 메뉴와 대화상자 모서리는 8px입니다.
- **로컬 검증**: JavaScript 805개 통과 · 2개 건너뜀, Rust 65개 통과와 타입 검사 · lint · 빌드 · 번들 검사 · clippy(1.99.0)를 확인했습니다. 진입 청크는 45KiB입니다. 개발용 화면 갤러리를 라이트 · 다크, 100 · 150% 배율로 찍어 바꾸기 전과 비교했고, 내보낸 HTML 예제의 메뉴도 브라우저에서 확인했습니다. GitHub **desktop** workflow에서 Windows 설치 · 서명 업데이트(재시작 확인 대화상자 포함) · 제거와 Linux deb/AppImage의 실제 WebKitGTK 화면 시험을 통과했습니다.
- **한계**: 앱 대화상자는 OS 대화상자와 달리 창 안에 뜨므로, 대화상자가 열린 동안에도 파일을 끌어다 놓을 수 있습니다. 파일이 바깥에서 바뀌었다는 경고가 떠 있는 동안에는 창 닫기 요청을 받지 않습니다. 오래된 Linux WebKitGTK에서 새 색 혼합 표현이 지원되지 않으면 일부 채움이 기본 모양으로 보일 수 있습니다. 이미 내보낸 HTML 파일은 바뀌지 않습니다.
