# view-anything v0.1.0 (Markdown 뷰어·편집기) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 탐색기에서 `.md`를 더블클릭하면 렌더링된 문서가 바로 뜨고, 편집 모드로 바꿔 Typora처럼 고친 뒤 **고친 블록만** 원문에 저장하는 Tauri 앱을 만든다. CI와 draft 릴리스 파이프라인까지 포함한다.

**Architecture:**
- 창 하나가 파일 하나를 연다. 경로는 URL 쿼리 `?file=`로 전달하고, Rust의 single-instance 플러그인이 파일마다 새 창을 띄운다.
- 읽기 모드는 unified(remark→rehype)로 만든 정적 HTML이라 가볍다.
- 편집 모드는 Milkdown Crepe를 lazy import한다.
- 저장은 순수 함수 `spliceMarkdown`이 담당한다. 에디터가 직렬화한 결과를 블록 단위로 diff해서 바뀐 블록만 원문 위에 덮어쓴다.

**Tech Stack:** Tauri 2, Rust, Vite 8, TypeScript (vanilla), unified/remark/rehype, KaTeX, highlight.js, mermaid, @milkdown/crepe, vitest, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-10-26-view-anything-design.md`

## Global Constraints

- 시작 속도가 핵심이다. 읽기 모드의 초기 번들에 Crepe, mermaid, three.js가 들어가면 안 된다. 이것들은 모두 dynamic `import()`로 불러온다.
- md 저장 규칙
  - 편집하지 않은 블록, frontmatter, HTML 블록은 원문 바이트를 그대로 보존한다.
  - 아무것도 고치지 않고 저장하면 파일을 쓰지 않는다.
- 읽기 모드에서는 문서가 수정될 수 없다.
- 창: 파일마다 새 창을 연다(single-instance + multi-window). 탭은 없다.
- 테마: 시스템 설정을 따르고 수동 토글을 둔다. 토글 값은 `localStorage` 키 `va.theme`(`"light" | "dark" | "system"`)에 저장한다.
- 버전: `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`의 버전은 항상 같아야 한다.
- 커밋 메시지: Conventional Commits 형식, scope 없이 쓰고, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` 트레일러를 붙인다.
- 파일 연결 대상 확장자(v0.1): `md`, `markdown`

## Review Focus

1. **CRLF 파일(Windows):** 편집한 블록을 다시 넣을 때 원문의 줄바꿈 방식을 따라야 한다. LF가 섞이면 안 된다. → Task 3 `splice preserves CRLF`
2. **UTF-8 BOM과 마지막 줄바꿈 유무:** 저장한 뒤에도 그대로 남아 있어야 한다. 원문이 UTF-8이 아니면(CP949 등) 읽기 전용으로 열고 경고를 띄운다. → Task 3 `decodeText`, `splice preserves BOM and missing trailing newline`
3. **한글이나 공백이 들어간 경로:** 탐색기 인자로 넘어올 때와 md 안의 상대 이미지 경로 양쪽 모두. → Task 1 `file_arg` 테스트, Task 4 `resolveAsset` 테스트
4. **저장하지 않고 닫거나 다른 md 링크로 이동할 때:** 확인 대화상자가 떠야 한다. → Task 5 `shouldConfirmLeave`
5. **에디터 재파싱으로 블록 수가 원문과 맞지 않을 때**(정의 링크, 연속 HTML 등):
   - 조용히 전체를 재직렬화하면 안 된다.
   - `SpliceError`를 던지고, UI는 "원문 보존 불가 — 전체 재작성으로 저장할까요?"라고 물어야 한다.
   - → Task 3 `splice throws on block count mismatch`

### Task 3: 텍스트 코덱과 `spliceMarkdown`(원문 보존 저장의 핵심)

**Files:**
- Create: `src/md/text.ts`, `src/md/splice.ts`, `tests/text.test.ts`, `tests/splice.test.ts`
- 의존성: `unified`, `remark-parse`, `remark-gfm`, `remark-math`, `remark-frontmatter`

**Interfaces:**
- Produces:
  - `decodeText(bytes: Uint8Array): { text: string; bom: boolean; eol: "\r\n" | "\n"; readOnlyReason?: string }`
    - `text`는 LF로 정규화한다.
    - 올바른 UTF-8이 아니면 `readOnlyReason`을 채운다.
  - `encodeText(text: string, meta: {bom, eol}): Uint8Array`
  - `splitBlocks(md: string): { start: number; end: number }[]`: mdast `root.children`의 position offset 목록
  - `spliceMarkdown(original: string, baseline: string, edited: string): string | null`
    - 입력은 모두 LF 정규화된 문자열이다.
    - `baseline`은 에디터가 원문을 로드한 직후 직렬화한 결과다.
    - 반환값 `null`은 변경 없음을 뜻한다.
    - 블록 수가 맞지 않으면 `SpliceError`를 던진다.

**알고리즘** (signature와 테스트만으로는 정해지지 않으므로 명시한다)
1. `edited === baseline`이면 `null`을 반환한다.
2. `O = splitBlocks(original)`, `B = splitBlocks(baseline)`을 구한다. 두 블록 수가 다르면 `SpliceError`를 던진다. `O[i]`와 `B[i]`는 1:1 대응한다.
3. `E = splitBlocks(edited)`를 구한다. 블록 텍스트를 기준으로 `B`와 `E`의 LCS 정렬을 계산한다.
4. 출력을 만든다.
   - `B`와 `E`에서 짝이 맞은 블록은 원문 `O[i]` 텍스트를 그대로 쓴다.
   - 블록 사이 구분자도 원문의 해당 갭을 그대로 쓴다.
   - `E`에만 있는 블록(새로 생긴 블록이나 수정된 블록)은 edited 텍스트를 쓴다. 블록 사이는 `"\n\n"`으로 잇는다.
   - 원문의 맨 앞 갭과 맨 끝 꼬리(trailing newline 유무 포함)는 그대로 둔다.

- [ ] **Step 1: 실패하는 테스트 작성**

```ts
const orig = "---\ntitle: x\n---\n\n* a\n* b\n\n| a |  b |\n|:--|--:|\n| 1 | 2 |\n\npara one\n\npara two";
// baseline: 에디터 직렬화를 흉내 냄 (목록 기호와 표 정렬이 바뀜)
const base = "---\ntitle: x\n---\n\n- a\n- b\n\n| a | b |\n| :- | -: |\n| 1 | 2 |\n\npara one\n\npara two\n";
test("no change returns null", () => expect(spliceMarkdown(orig, base, base)).toBeNull());
test("only edited block changes", () => {
  const out = spliceMarkdown(orig, base, base.replace("para two", "para 2"))!;
  expect(out).toBe(orig.replace("para two", "para 2"));
});
test("inserted block lands between original neighbours", () => {
  const out = spliceMarkdown(orig, base, base.replace("para one\n", "para one\n\nnew\n"))!;
  expect(out).toBe(orig.replace("para one\n", "para one\n\nnew\n"));
});
test("deleted block removes only that block", () => { /* para one 삭제 → orig에서 "para one\n\n" 만 제거 */ });
test("splice throws on block count mismatch", () => {
  expect(() => spliceMarkdown("a\n\nb", "a b", "a c")).toThrow(SpliceError);
});
test("decodeText detects BOM and CRLF, encodeText round-trips bytes", () => {
  const bytes = new Uint8Array([0xEF,0xBB,0xBF, ...new TextEncoder().encode("# 한\r\n\r\nx")]);
  const d = decodeText(bytes);
  expect(d).toMatchObject({ bom: true, eol: "\r\n", text: "# 한\n\nx" });
  expect(encodeText(d.text, d)).toEqual(bytes);
});
test("splice preserves CRLF and BOM and missing trailing newline", () => { /* decode → splice → encode 후 수정 블록 외 바이트 동일 */ });
test("non-utf8 bytes are read-only", () => {
  expect(decodeText(new Uint8Array([0xC7,0xD1])).readOnlyReason).toBeTruthy();
});
```
