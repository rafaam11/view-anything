# v0.3.0 — 포인트클라우드 검사·정리·저장

2026-10-27 사용자 인터뷰 승인. 기존 3D 장면에 PCD/PLY를 통합하고, 원본을 보존하는 작업본에서 영역 선택 → 필터 → 동일 형식 다른 이름 저장을 제공한다.

## 확정 범위
- 장면 합계 1천만 점, 원본 디코딩 2GiB/세션, 예상 작업 메모리 8GiB/앱. Windows/Linux, Rust 백그라운드 처리와 three.js 표시. kiddo 6.3.0 정확 이웃 검색.
- PCD ASCII/binary/binary_compressed 읽기, binary 쓰기. PLY ASCII/LE/BE 읽기, LE 쓰기. 모든 점 scalar/list 속성 보존. PLY mesh는 기존 경로 유지, 안전하지 않은 비점 요소는 편집 제한.
- 좌표 계산 f64, 표시 f32+원점 이동. 원본 좌표와 VIEWPOINT를 자동 변환하지 않는다. 유효하지 않은 좌표는 표시/처리 제외하고 개수를 알린다.
- RGB/단색/높이/intensity, 점 크기 1~10px(기본 2), GPU ID 점 조회. 3D 축 정렬 박스(핸들+수치)와 화면 다각형 관통 선택; 단면 적용, 경계 포함, Esc 취소.
- Voxel은 파일 원점 기준 복셀 중심에 가장 가까운 원본점(동률 ID순); SOR k=20, 모표준편차 배수 2; 반경 필터 최소 이웃 5(자신 제외). 거리 입력은 필수 양수, 단위 추측 없음.
- 선택 남기기/삭제, 처리 결과 미리보기/적용/취소, 최대 20회 undo/redo. 원본 레코드 공유와 점 ID 집합으로 이력 관리. 처리 실패/취소/오래된 revision은 작업본 불변.
- PCD→PCD, PLY→PLY만 저장. 원본 덮어쓰기 금지, 기본 `_edited`, 다른 대상 덮어쓰기는 확인, 원자적 교체. organized PCD는 변경 없으면 보존, 점 제거 후 HEIGHT=1.
- 창/객체 제거 및 다중 창 업데이트에서 미저장 작업 보호. 창 소유 세션과 앱 전체 계산 직렬화, 진행률/취소, 종료 시 자원 회수.
- HTML은 현재 작업본 표시 좌표/색상/점 크기를 담은 보기 전용. 사용자 정의 속성/편집/PCD·PLY 저장 제외를 안내.
- 후속: LAS/LAZ, ICP, 형상 분석, 상호 형식 변환, 디스크 기반 초대형 처리.

## 구현 순서와 완료 기준
1. Rust 파일/데이터 계층: 모든 인코딩·속성·조직화·손상/overflow 테스트.
2. 장면/표시/선택: 큰 좌표, 좌표계, 단면, 혼합 장면, 정확한 점 조회.
3. 필터/이력/저장 보호: 작은 완전탐색 oracle, 경계/중복/빈 결과/취소/자원 회수, 다중 창 보호.
4. HTML/성능/릴리스: 합성·공개 데이터만 사용. 32GB 개발 PC에서 1천만 XYZRGB 첫 표시/선택/Voxel 10초, SOR/반경 각 60초 목표; 앱 메모리 증가 8GiB 이내, UI 500ms 이상 정지 없음, 취소 버튼 100ms 이내. 라이브러리 호출 취소 지연은 실측 기록.

각 단계 npm test, npx tsc --noEmit, npm run build, npm run check:bundle, cargo test --manifest-path src-tauri/Cargo.toml 통과 후 main에 scope 없는 Conventional Commits. 마지막 v0.3.0 draft 생성/첨부/서명 확인; 공개 발행은 별도 승인.
