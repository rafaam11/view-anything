# 기본 사용성 보완 검증

대상: v0.10.0 이후 main의 이미지 이력·폴더 갱신·현재 뷰어 설정·TXT 표시 옵션과 원본 삭제 후 이미지 복구 저장. 공개 설치본의 변경이 아닌 별도 식별자의 Windows 개발 WebView에서 검증했다.

## 자동 검증

각 구현 작업의 `npm test`, `npx tsc --noEmit`, `npm run build`, `npm run check:bundle`, `cargo test --manifest-path src-tauri/Cargo.toml`을 통과했다. 최종 로컬 결과는 JS 561 passed/2 skipped, Rust 51 passed다. Unix의 심볼릭 링크 회귀는 Linux CI에서 수행한다.

- 합성 변환의 자르기 경계·회전/반전, 20회 제한, redo 분기 폐기, 저장 체크포인트.
- 편집 모드 분리, 복사/저장 오류 후 편집과 이력 유지, 원본/폴더 갱신 오류, 썸네일 재구성.
- 구버전 Markdown 설정 이관, TXT 옵션 검증·저장·동기화, 그룹별 초기화, 설정과 본문·선택·미저장 상태 분리.
- 원본이 삭제된 뒤에도 다른 경로 저장 허용, 원본 경로/Windows 대소문자 별칭 저장 거부, 원본 폴더 미재생성. 끊어진 링크를 추측하지 않는 보호.

## 실제 Windows GUI 검증

Playwright CDP를 별도 Tauri 앱의 실제 WebView에 연결했고 computer-use로 화면과 버튼 조작도 확인했다. 아래 항목은 단위 테스트 결과와 구분한다.

| 흐름 | 확인 결과 |
| --- | --- |
| 이미지 회전→자르기→반전, undo/redo·분기 | 각 픽셀을 합성 원본과 비교, 원본 복원과 redo 분기 폐기 확인 |
| 이미지 PNG 저장 후 undo/redo | 저장 상태의 미저장 표시 해제, 다른 상태에서 미저장 보호, 저장 PNG를 별도 System.Drawing으로 크기·픽셀 확인 |
| 폴더 파일 추가·삭제와 F5 | 썸네일·이전/다음 갱신, 현재 이미지 표시, 자르기 입력에 포커스가 있어도 앱 재로드 없음 |
| 원본 삭제·손상 대상·폴더 접근 실패 | 표시 이미지·편집 이력 유지, 이동 취소, 오류 후 정상 파일 이동·목록 복구 |
| 원본 파일·폴더 삭제 후 복구 저장 | 다른 PNG 저장 및 픽셀 확인, 대소문자가 다른 원본 경로는 거부, 삭제된 원본·폴더를 재생성하지 않음 |
| 뷰어별 설정 | Markdown/TXT/명시적 텍스트 열기/이미지/JSON/CSV/PDF/3D/빈 창에서 해당 항목만 표시 |
| TXT 설정과 안전 편집 | 글꼴·크기·줄바꿈·테마 다중 창 동기화, 잘못된 크기 거부, 그룹별 초기화, 설정 변경 후 네이티브 텍스트 undo 유지 |
| TXT 검색·저장·인코딩 취소 | 긴 줄의 줄바꿈·가로 스크롤 검색 위치, BOM·CRLF 보존 저장, 미저장 상태에서 인코딩 변경 취소 시 편집 유지 |
| 새 프로세스 재시작 | TXT 글꼴·크기·줄바꿈 복원, 읽기 모드 유지, 파일별 인코딩은 전역 설정에 저장하지 않음 |
| computer-use | 화면 확인 후 편집 아이콘, 회전, 실행 취소를 클릭하고 도구/미저장 표시 전환 확인 |

GUI 시험 스크립트는 OS Temp의 `va-browser-check/usability-{history,folder,settings,restart,recovery}.mjs`, 화면은 `va-usability-*.png`에 보관했다. 합성 데이터만 사용했으며 저장 대화상자와 일부 오류/미저장 확인 응답은 시험 경로·응답으로 대체했다. 폴더 활성화는 실제 WebView의 focus 이벤트를 발생시켜 검증했고 물리적 창 전환 입력으로 간주하지 않는다. Windows PNG 디코딩, 파일 읽기/쓰기와 복구 저장 보호는 실제 네이티브 경로를 사용했다.

## 남은 범위

- Linux 실제 GUI, 설치본 파일 연결·업데이터 설치는 미검증이다.
- 폴더는 활성화/F5/저장 후 갱신하며 실시간 파일 감시는 제공하지 않는다. 썸네일은 1,000개까지 표시한다.
- 이미지 이력은 최근 20회이며 다른 파일을 열거나 외부 변경으로 원본을 다시 읽으면 초기화한다. GIF/SVG는 정적 편집 결과다.
- 텍스트는 10 MiB까지이며 구문 강조·대용량 로그 스트리밍은 제공하지 않는다. 외부 프로세스의 검증·파일 교체 사이 경쟁은 여전히 남는다.

## 다음 페이즈 제안

1. **설치·업데이트 회귀**: 격리 Windows 시험 환경에서 설치→TXT/PNG/PDF/PCD 더블클릭→미저장 창이 있는 업데이트 취소/재시도→업데이트 후 재열기→제거를 반복한다. 원문 해시·미저장 내용 보존과 연결 프로그램 등록/해제를 통과 기준으로 삼고 재실행 가능한 시험 스크립트와 결과를 남긴다. 사용자 사용 중인 설치본은 시험 대상으로 삼지 않는다.
2. **Linux GUI 검증**: deb와 AppImage 각각에서 텍스트 편집/줄바꿈/인코딩, 이미지 복사·undo/복구 저장, 3D/점군 조작과 오프라인 HTML을 실제 데스크톱으로 확인한다. 지원 환경의 배포판·디스플레이 구성을 명시하고 자동 검사와 실제 GUI 증거를 분리해 기록한다.
3. **규모 확장 계획**: 위 두 단계 이후 1만 이미지 폴더의 썸네일 가상화와 100 MiB 로그의 읽기 전용 스트리밍을 각각 설계한다. 임시 합성 파일로 최초 표시 시간·탐색 응답·피크 메모리를 측정해 목표를 정하고, 기존 안전 편집 한도와 구문 강조 범위를 함께 결정한다.
