# v0.16.0 UI 일관성 정비 — 버튼·대화상자·알림을 Windows 11 방식으로 통일

## Context

사용자가 업데이트 재시작 팝업의 버튼이 올드하다고 지적하고, UI 통일성을 해치는 부분을 전수조사해 고치자고 했다. 조사(CSS 14개 파일 전체, TS의 UI 생성 코드 전체) 결과는 다음과 같다.

- **업데이트 대화상자 버튼은 브라우저 기본 회색 버튼이다.** 공용 컨트롤 규칙(`src/ui/chrome.css:3-4`)이 `.va-viewer`/`.va-settings`/`.pdf-password` 범위에만 걸려 있어 body 직속 `<dialog class="va-update-dialog">`(`src/update/badge.ts:66-90`)가 빠졌다. 대화상자 padding도 없다.
- **스타일 기준이 없다.** 버튼 padding 10종 이상, 포커스 링 4종(`#5384df` 하드코딩 포함), hover 방식 5종, 배경막 3종, 팝오버 그림자 5종, 모서리 0/2/3/4/6/8/12px, mono 글꼴 3종, 빨강 3종이 섞여 있다. `accent-color`가 없어 체크박스·슬라이더가 기본 파랑이다. `.md-banner`는 시스템+다크에서 밝은 노랑으로 남는다.
- **확인창이 둘로 갈린다.** 버리기·교체·경고는 OS 기본 대화상자(`src/platform.ts:101-133`)인데 업데이트만 앱 대화상자다. `confirmDanger`의 안전 버튼 라벨이 문맥과 무관하게 "저장 안 함"으로 고정돼 있다.
- **동작·문구가 제각각이다.** 저장 성공은 상태줄·모달·빨간 오류 배너로 나뉜다. 저장 충돌은 상태줄과 alert로 나뉜다. 찾기 UI는 md(아이콘)·PDF(혼합)·텍스트(글자) 3종이다. 버리기 문구 6종, 지역 `button()` 헬퍼 5개, 파일 메뉴 구성도 뷰어마다 다르다.

사용자 결정(객관식):
- **시각 스타일**: Windows 11 풍. 모서리 6px, 테두리 없는 옅은 채움 보조 버튼, 강조색 채움 주 버튼과 흰 글자, 위험은 빨강, 대화상자 버튼 오른쪽 정렬, 높이 32px.
- **확인창**: OS 대화상자를 앱 대화상자 하나로 통일한다. 안전한 쪽이 기본이다. 성공 알림은 모달 대신 비모달로 보낸다.
- **범위**: 보이는 것과 동작 전부.

목표는 v0.16.0(minor)으로 릴리스하는 것이다(태그와 draft까지, 공개 발행은 사용자 요청 시).

## 내가 정한 판단 (사용자 확인 필요 시 번복 가능)

- **다크 주 버튼 색**: Win11 다크 강조색 `#60CDFF`에 흰 글자는 명암비 1.8:1이라 읽을 수 없다. 다크 채움은 `#0067C0`(흰 글자 5.7:1)로 두고, 링크·텍스트 강조는 `--accent-text: #60CDFF`로 분리한다.
- **"업데이트 확인" 메뉴**: 3D 파일 메뉴의 항목(툴팁이 개발 메모 "다음 작업에서 연결")을 지운다. 모든 창의 업데이트 배지 메뉴 첫 항목이 같은 일을 하고, 그 항목에 `Ctrl+Shift+U`를 표시한다.
- **커서**: Windows 관례대로 컨트롤 커서를 `default`로 통일한다(지금 pointer/default 혼재).
- **md 링크·목차 색**: 전역 `--accent-text`로 합친다. 라이트 `#0969da`→`#005fb8`, 다크 `#58a6ff`→`#60cdff`로 조금 바뀐다.
- **미루는 것**: 3D 패널 글리프(▶●○⋯×)는 `aria-label`만 붙이고 모양은 유지한다. 텍스트·CSV·JSON에 `Ctrl+E` 추가는 하지 않는다.
- **함께 고치는 기존 버그**:
  - 업데이트 소유 창이 최소화돼 있으면 재시작 대화상자가 안 보여 모든 창이 잠긴 채 남는다(`setFocus`가 복원하지 않음).
  - 텍스트·PDF 찾기에서 한글 조합 확정 Enter가 검색을 실행한다(`isComposing` 검사 없음).
  - HTML 런타임에 `menu.css`가 실제로는 인라인되지 않는다.

## 설계

### 1. 토큰 — 새 `src/ui/tokens.css`(테마 색의 유일한 정의 위치)
- `styles.css`의 `:root` 세 블록을 옮긴다. `main.ts`가 가장 먼저 import한다.
- HTML 런타임은 `?inline`으로 같은 파일을 넣고 `data-theme="system"`을 지정해, 지금처럼 OS 설정을 따른다.
- 값(라이트 / 다크):
  - 배경과 글자: `--bg #fff/#0d1117`, `--bg-overlay #fff/#161b22`, `--bg-inset #f6f8fa/#010409`, `--fg`·`--muted`·`--border`는 지금 값
  - 강조: `--accent #005fb8/#0067c0`, `--accent-text #005fb8/#60cdff`, `--on-accent #fff`
  - 위험: `--danger #c42b1c`, `--danger-active #a92317`(제목줄 닫기와 같음), `--danger-text #c42b1c/#ff99a4`
  - 경고와 오류 바탕: `--warning #9d5d00/#fce100`, `--warning-bg #fff4ce/#433519`, `--error-bg #fde7e9/#442726`
  - 배경막과 그림자: `--backdrop rgb(0 0 0/.3)/.5`, `--shadow-low` · `--shadow-popover` · `--shadow-dialog`(Win11 elevation, 다크는 불투명도 상향)
  - 채움(테마 무관 color-mix): `--fill-control` fg 7%, hover 11%, active 5%, `--fill-subtle-hover` 8%, `--fill-selected` accent-text 18%, `--info-bg`
  - 모양: `--focus-ring: 2px solid var(--fg)`, `--radius-sm 4px`(메뉴 항목·행), `--radius 6px`(버튼·입력), `--radius-lg 8px`(메뉴·대화상자·toast·배너·떠 있는 상자)
  - 글꼴과 크기: `--font-ui`, `--font-mono`(`settings/preferences.ts`의 `FONTS.mono`와 같은 문자열), `--font-size-ui 13px`, `--font-size-small 12px`, `--font-size-title 20px`, `--control-h 28px`, `--control-h-lg 32px`, `accent-color: var(--accent)`
- `::backdrop`은 `var(--backdrop, rgb(0 0 0/.3))`처럼 대체값을 쓴다. 오래된 WebKitGTK가 변수를 상속하지 않기 때문이다.
- 다크 값은 미디어 블록과 `[data-theme=dark]` 블록 두 곳에 쓰고, 테스트가 두 블록이 같은지 지킨다.

### 2. 기본 컨트롤 계층 — 새 `src/ui/base.css`(앱은 tokens 다음 import, 런타임은 `?inline`)
- `:where()`로 감싼 영명시도 baseline(`.md-editor` 내부 제외)으로, 어떤 버튼·입력도 브라우저 기본 모양이 되지 않게 한다.
  - 버튼: `--fill-control` 바탕, 테두리 없음, `--radius`
  - 입력: 1px `--border` 테두리, 포커스 시 Win11 밑줄 `inset 0 -2px 0 var(--accent)`
  - `:focus-visible`: `--focus-ring`, 오프셋 1px
- 클래스:
  - `.va-btn`(보조), `.va-btn-primary`, `.va-btn-danger`, `.va-btn-ghost`: 높이 `--control-h`, `padding 0 12px`, 13px
  - `.va-icon-button`: 28×28, svg 18px, ghost, `[aria-pressed=true]`는 `--fill-selected`
  - `.va-banner[data-kind=info|warning|error]`
- **원칙(AGENTS.md에 기록)**: 컨테이너 규칙(`.foo button`)은 배치만 정한다. 모양은 baseline, 클래스, 정해진 특수 위젯(제목줄, 업데이트 칩, 썸네일, 3D 트리 행)만 정한다. `tests/base-css.test.ts`가 이를 검사한다.
- 정리할 곳:
  - `chrome.css`: 3-9, 15-17, 24행 등 컨트롤 모양 규칙 삭제
  - `titlebar.css`: subtle fill, 안쪽 포커스 링, 닫기는 `--danger`
  - `menu.css`: 메뉴 팝오버는 `--bg-overlay`, `--radius-lg`, `--shadow-popover`
  - `three.css`: 아이콘 버튼·도구줄 버튼 중복 삭제, 선택 행과 제거 hover를 토큰으로, 배너는 `.va-banner`, 메뉴 중복 규칙(171-215행)은 Phase 7에서 삭제
  - `pointcloud.css`, `settings.css`, `update.css`(`#5384df` 삭제), `text/viewer.css:4-5`, `md.css`의 `.md-toggle` 삭제와 `.md-banner` 시스템 다크 수정, `pdf/viewer.css`의 `#8886`·`#7774`·미정의 `--va-fg`, 이미지 현재 썸네일

### 3. 앱 대화상자 — 새 `src/ui/dialog.ts`(Tauri 없음)
```ts
showDialog<T extends string>(o: { title?: string; message: string; detail?: string;
  kind?: "info"|"warning"|"error"; buttons: readonly { label: string; value: T; variant?: "primary"|"secondary"|"danger" }[];
  defaultValue: T; cancelValue: T; className?: string }): Promise<T>
initializeDialogInput(): () => void
```
- DOM: `<dialog class="va-dialog va-message" role=dialog|alertdialog>`에 kind 아이콘, 제목, 본문, 상세, 오른쪽 정렬 푸터를 둔다.
- 모양: 푸터는 `--bg-inset` 바탕, 버튼 최소 높이 32px·최소 폭 96px이다. 표면은 `min(440px, 100vw-32px)`이고, 작은 창에서는 본문이 스크롤된다.
- 문자열은 전부 textContent로 넣는다. `aria-labelledby`와 `aria-describedby`를 둔다.
- 포커스: 안전한 기본 버튼에 포커스한다. Esc와 외부 close는 `cancelValue`다(Chromium이 `cancel` 없이 close할 수 있어 둘 다 처리). 닫으면 이전 포커스를 복원한다. 여러 개는 top layer에 쌓인다.
- **키 가드 `initializeDialogInput`**: window capture keydown을 하나 둔다. `main.ts`의 `initializeUpdateInput()` 바로 다음에 호출한다.
  - `.va-message[open]`이 있을 때만 동작하며, 모든 앱 단축키를 `stopImmediatePropagation`으로 막는다.
  - 대화상자 안의 Tab, Enter, Space, Esc, 좌우 화살표만 기본 동작을 허용한다.
  - 반복 입력 Enter와 Space는 막는다.
  - 이유: OS 대화상자와 달리 앱 모달은 window 키 리스너를 막지 못한다. main의 Ctrl+O, 텍스트 Ctrl+S, 3D 키, 점군 Esc 등이 새어 나간다.
- **업데이트 잠금**: `src/update/guard.ts`의 `closest(".va-update-dialog")`를 `closest(".va-message")`로 바꾼다. 잠금 중 뜬 닫기 확인도 조작할 수 있다.
- **`src/platform.ts` 래퍼**: 시그니처를 유지하고 선택 인자만 추가한다. 별표가 기본 포커스 버튼이며 Esc도 그 값이다.
  - `confirm(text, okLabel="계속", kind="warning")`: [ok][취소*]
  - `confirmDiscard(text, discardLabel="버리기")`: [버리기(danger)][취소*]. 3버튼을 2버튼으로 줄인다.
  - `confirmDanger(text, dangerLabel, safeLabel="취소")`: [danger][취소*]
  - `notice(text, kind="info")`, `alert(text)`: [확인*]
  - `bringToFront()`: 최소화돼 있으면 `unminimize`하고 `setFocus`한다. 모든 래퍼가 표시 전에 부른다.
  - import는 `open`과 `save`만 남긴다.
- **`onCloseRequested`**: 확인이 이미 떠 있으면 중복을 막는다. 예외가 나면 `window.confirm`으로 대체하고 문구만 통일한다.
- **권한(`src-tauri/capabilities/default.json`)**: `core:window:allow-unminimize`를 추가한다. `dialog:default`를 `dialog:allow-open`과 `dialog:allow-save`로 좁힌다.
- **`confirmRestart`(`badge.ts`)**: showDialog로 다시 만든다.
  - `className: "va-update-dialog"`를 쓰고, 제목·문장·버튼 이름(취소/재시작)을 유지한다. `scripts/desktop/windows.mjs`가 이 값들에 의존한다.
  - dirty면 재시작 버튼을 danger로 한다.
  - `update/main.ts`의 `approve`는 `setFocus`를 `bringToFront`로 바꾼다.
- **설정·PDF 암호 대화상자**: 같은 `.va-dialog` 표면, 제목·본문·푸터 구조로 맞춘다. 설정의 "닫기" 라벨은 유지한다(`linux.mjs`가 의존). PDF 암호는 [열기(primary)][취소]다.

### 4. 피드백 규칙과 toast — 새 `src/ui/toast.ts`, `src/ui/strings.ts`
- **규칙(AGENTS.md에 기록)**:
  1. 성공(저장·복사·내보내기)은 toast.
  2. 지속 상태(읽기 전용 사유·혼합 줄바꿈·CP949·구문 오류·진행률)는 상태줄이나 warning 배너.
  3. 사용자 동작의 실패는 alert.
  4. 외부 변경 충돌은 `notice(…, "warning")`.
  5. 되돌릴 수 없는 동작은 confirm 계열, 안전한 쪽이 기본.
  6. 배경 작업의 실패와 안내는 3D 배너(kind) 또는 상태줄이고, 모달은 쓰지 않는다.
- **toast**: `toast(message, { timeout? })`로 띄운다.
  - body에 요소 하나만 두고 재사용하며, `role=status`, `aria-live=polite`, textContent다.
  - 기본 시간은 `min(6000, 2000+60×글자수)`ms다.
  - 위치는 아래 가운데 40px, z 95다(배지 90과 제목줄 100 사이). 진입 청크에 들어간다.
- **공용 문구(`strings.ts`)**: `SAVED "저장했습니다"`, `COPY_SAVED`, `DISCARD "저장하지 않은 변경 내용을 버릴까요?"`, `DISCARD_CLOSE`(+"닫기"), `DISCARD_RELOAD`(+"다시 읽기"), `CONFLICT_RELOAD`, `CONFLICT_READ_MODE`(md), `errorMessage(e)`("Error: " 접두 제거).
- **바꿀 호출처(대표)**:
  - text·csv·json의 "저장됨"/복사본 상태줄 → toast. 충돌 → `notice(warning)`.
  - md: 저장 성공 toast 추가. 복사본은 모달 대신 toast, 충돌은 `notice(warning)`, 링크 대상 없음은 alert, 실행 파일 차단은 `notice(warning)`, 재작성 문구 다듬기.
  - image: PNG 저장 모달 → toast. 복사 상태줄 → toast.
  - 3D: PNG 성공 빨간 배너 → toast, 실패는 alert. HTML 내보내기 성공 toast 추가. confirm 라벨은 "내보내기"·"저장".
  - 점군: "저장 완료" → toast. 상태줄과 배너 중복 오류 → 배너만. 닫기와 제거는 상황별 라벨.
  - main: 최근 파일 제거 알림 → toast. 오류 화면은 `errorMessage`.
  - 각 뷰어의 `confirmLeave`는 상황 라벨을 받는다(닫기 요청은 `DISCARD_CLOSE`·"닫기").
- **3D 배너**: `Banner`를 `src/three/core/banner.ts`로 옮겨 런타임과 공유한다.
  - `show(msg, action?, kind="error")`와 `info(msg)`를 둔다. role은 error면 alert, 그 밖은 status다.
  - 닫기는 `iconButton("닫기","close")`다.
  - 진행 중 거부 안내는 info, 로드 실패는 error, 메타 경고는 warning이다.

### 5. 찾기 막대 — 새 `src/ui/find-bar.ts`
- `findBar({ label, maxLength?, step(back), input?(), close?() })`는 `{ element, input, count, isOpen, open(), close() }`를 돌려준다.
- 구성은 떠 있는 `.va-find`(md 방식 위치 규칙을 일반화해 `chrome.css`에 둠)와 search input, `.va-find-count`, `iconButton` 이전 결과(Shift+Enter)·다음 결과(Enter)·찾기 닫기(Esc)다. `isComposing`일 때는 넘긴다.
- 결과 표시는 count로 통일한다: md `1/3`, PDF `2페이지 · 1/3`, 텍스트 `12번째 문자`, 없으면 "결과 없음".
- md(`src/md/find.ts`)·PDF·텍스트가 함께 쓰고, 각 뷰어의 검색 로직은 유지한다.

### 6. 버튼·라벨·메뉴
- **버튼 헬퍼**: `textButton(label, variant="secondary", { shortcut?, title? })`와 `menuButton(label, shortcut?)`를 `src/ui/icons.ts`에 둔다. 둘 다 `type=button`과 클래스를 강제한다.
  - 지역 헬퍼 5개를 교체한다: `image/viewer.ts:22`, `pdf/viewer.ts:15`, `three/cloud/controller.ts:130`, `text/viewer.ts:30`, `three/core/panel.ts:25`(aria-label만 추가).
  - 모든 `createElement("button")` 위치에도 적용한다.
- **편집 전환**: md·텍스트·CSV·JSON 모두 `textButton("편집")`(↔"읽기")이다. md의 테스트 훅 `md-mode-toggle`은 유지한다. 이미지는 아이콘 버튼에 누름 상태만 맞춘다.
- **CSV 페이지·열 이동**: 아이콘 버튼으로 `[‹] 1 / 5 [›] · 열 [‹] 1 / 2 [›]`처럼 둔다. **이미지 자르기**는 [자르기 적용(primary)][취소]다.
- **파일 메뉴**: `fileMenu(close, { open?, actions?, files? })`가 순서를 하나로 정한다.
  - 순서: 열기… / 텍스트로 열기… / 뷰어별 열기 항목 → 최근 파일 → 뷰어별 작업
  - `documentBar`, 텍스트 뷰어(`documentBar`로 이전), 3D가 함께 쓴다.
  - 3D에는 "텍스트로 열기…"를 추가하고 "업데이트 확인"은 삭제한다.
  - 쓰지 않는 `tools`와 `command()`는 삭제한다.
- **단축키 표시**: `data-shortcut` + CSS `::after`로 오른쪽 회색 글씨로 표시한다(textContent 불변).
  - 대상: md·CSV·JSON 저장 `Ctrl+S`, 이미지 "PNG로 저장…" `Ctrl+S`, "파일 경로 복사" `Ctrl+Shift+C`(라벨 괄호 제거), "화면에 맞춤" `Ctrl+0`
  - 말줄임은 추가 입력을 받는 항목에만 붙인다: "다른 이름으로 저장…", "PNG로 저장…".
- **빈 화면·오류 화면(`main.ts`)**:
  - 빈 창: 제목 "파일을 끌어다 놓거나 여세요", 버튼 [열기…(primary)][텍스트로 열기…], 그 아래 최근 목록.
  - 실패 화면: `role="alert"`, 버튼 "이 파일을 텍스트로 열기".
  - 함께 고침: 파일 메뉴의 최근 항목 말줄임, 구문 강조 안내를 "100만 자"로.

### 7. HTML 런타임(`src/three/export-runtime/main.ts`)
- 스타일 순서: tokens → base → `menu.css?inline`(누락 버그 수정) → `BASE_CSS`(html/body/.va-notice/frame-label만) → three.css. 같은 커밋에서 `three.css`의 메뉴 중복 규칙을 지운다.
- 안내는 공용 `Banner`(info, 닫기 버튼 있음)를 쓰고, PNG 실패는 `window.alert` 대신 같은 배너의 error로 띄운다. 이미 내보낸 파일은 영향이 없다.
