# v0.2.0 수동 확인 체크리스트 (Task 9)

자동 테스트(vitest, cargo)와 번들 가드로는 확인할 수 없는 GUI·설치·메모리 항목이다. 모두 통과하면 릴리스 노트(`docs/release/v0.2.0.md`)의 수치를 확정하고 릴리스 단계로 넘어간다. 3D 시험 파일은 `tests/fixtures/3d/`에 있고, 큰 STL은 `node scripts/bench-stl.mjs 3000000 --keep`로 임시 폴더에 만든다(출력된 경로를 쓰고, 끝나면 지운다).

## 1. 설치와 파일 연결 (Windows NSIS)
- [ ] `npm run tauri build -- --bundles nsis`로 만든 설치 파일 크기를 기록한다(v0.1.0은 4.6MB, occt wasm 약 7.6MB 추가). 릴리스 노트의 "설치 파일 크기 증가" 항목에 실제 값을 적는다.
- [ ] `.stl`, `.step`, `.stp`, `.iges`, `.igs`, `.obj`, `.ply`, `.gltf`, `.glb`를 더블클릭하면 3D 창으로 열린다(대문자 확장자 `.STEP` 포함).
- [ ] md 콜드 스타트가 v0.1 수준(약 0.6초)에서 회귀하지 않았다(3회 측정).

## 2. 탐색기 드래그 & 드롭
- [ ] 3D 창에 STL을 놓으면 같은 장면에 추가되고, 이어서 STEP을 놓으면 그것도 추가된다(순서대로 큐 처리).
- [ ] 3D 창에 `.md`를 놓으면 새 창으로 열린다.
- [ ] **Shift+드롭**: 3D 창에 Shift를 누른 채 3D 파일을 놓으면 새 창으로 열린다. 창에 포커스가 없을 때(다른 창을 클릭한 뒤 탐색기에서 끌어올 때)도 Windows에서는 동작해야 한다.
- [ ] 빈 창에 STL 2개와 md 1개를 함께 놓으면: 첫 3D 파일은 그 창에서 열리고, 나머지 3D 파일은 추가되며, md는 새 창으로 열린다.
- [ ] md 창에 3D 파일을 놓으면 새 창으로 열린다(v0.1 규칙 유지).
- [ ] 3D 창의 Ctrl+O, 파일 > 장면에 추가도 같은 규칙을 따른다.

## 3. 메뉴바와 키보드
- [ ] Alt+F로 파일 메뉴, Alt+V로 보기 메뉴가 열린다. 한글 입력 상태(IME)에서도 열린다. 열린 상태에서 다른 메뉴 제목에 마우스를 올리면 전환되고, Esc나 바깥 클릭으로 닫힌다.
- [ ] Ctrl+Shift+E로 HTML 내보내기가 실행된다(한글 입력 상태 포함).
- [ ] F(전체 맞춤), 1~7(표준 뷰)이 패널의 입력 칸에 포커스가 있을 때는 동작하지 않는다.

## 4. 좌표계 프리셋 (시각 확인)
- [ ] `tests/fixtures/3d/assembly.glb`와 `cube.step`을 함께 열고, 화면 좌표계를 Y-up 왼손(Unity), Z-up 왼손(Unreal)으로 바꾼다. 면이 뒤집혀 보이지 않고(조명이 바깥 면에 맞고), 축 라벨이 프리셋대로 놓인다.
- [ ] 왼손 프리셋에서 단면 X/Y/Z 슬라이더가 화면 축 방향대로 자르고, 커서 좌표 값이 화면 축 기준으로 맞다.
- [ ] 객체별 원본 좌표계/단위(⋯ 메뉴)를 바꾸면 그 파일만 움직이고, 커서 좌표에 "(원본: …)"이 함께 나온다.

## 5. HTML 내보내기 (앱에서)
- [ ] 텍스처가 있는 glTF(`tests/textured-glb.ts`로 만드는 것과 같은 형태, 또는 실제 텍스처 모델)를 열고 내보낸 HTML을 **네트워크를 끈 상태**의 Chrome과 Edge에서 연다. 텍스처가 보이고, DevTools 네트워크 탭에 외부 요청이 없다.
- [ ] 내보낸 HTML이 내보낸 시점의 카메라, 숨김 상태, 표시 모드, 단면으로 열린다. 숨긴 파일은 들어 있지 않다.
- [ ] 50MB를 넘는 장면을 내보내면 저장 전에 확인 창이 뜬다.

## 6. 대용량과 메모리
- [ ] 150MB 합성 STL: 진행률이 읽기 → 파싱 → 업로드 순으로 움직이고, 로딩 중에도 창 이동·회전이 끊기지 않는다(DevTools Performance에서 200ms 이상 Long Task가 없는지 확인). 로드 시간을 기록한다.
- [ ] 같은 파일에서 솔리드+엣지로 바꾸면 "엣지 표시" 진행률이 뜨고, 그동안 UI가 반응한다. 엣지가 계산되는 동안 그 파일을 ×로 지우면 작업이 멈추고(작업 관리자에서 CPU가 내려감) 다른 파일의 엣지는 계속 만들어진다.
- [ ] **100MB STEP**: 작업 관리자에서 메모리 최고치를 기록한다. 메모리 부족으로 실패하면 "정밀도를 낮춰 다시 시도" 버튼이 나오고, 다시 시도하면 열린다. 로드가 끝나면 워커가 종료되어 메모리가 내려간다.
- [ ] 파일 추가·제거를 10회 반복한 뒤 메모리(작업 관리자의 WebView2 프로세스)가 처음 수준으로 돌아온다. 자동 테스트는 dispose 호출만 확인하므로 실제 GPU 메모리는 여기서 본다.

## 7. Linux 빌드
- [ ] ubuntu-22.04에서 `npm run tauri build`로 deb와 AppImage를 만들고 설치한다.
- [ ] STL, STEP 파일을 열고, 드롭으로 추가된다. occt wasm이 로드된다(CSP `wasm-unsafe-eval`).
- [ ] Shift+드롭: 창에 포커스가 있는 상태에서 Shift를 누르고 끌어 놓으면 새 창으로 열리는지 본다. 포커스가 없을 때 동작하지 않는 것은 알려진 제한이다(릴리스 노트에 기재).
- [ ] 파일 연결(.desktop의 MimeType)로 더블클릭 열기가 되는지 본다.
