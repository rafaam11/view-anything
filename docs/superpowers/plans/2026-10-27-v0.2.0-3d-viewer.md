# view-anything v0.2.0 (3D 뷰어) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** STL/OBJ/PLY/glTF/GLB/STEP/IGES 파일을 더블클릭하면 3D 뷰어가 열린다. 3D 파일을 드롭하면 같은 장면에 추가(append)되고, 장면을 앱과 같은 기능을 가진 단일 오프라인 HTML로 내보낼 수 있다.

**Architecture:**
- 3D 뷰어는 `src/three/viewer.ts`이며 lazy import로만 불러온다(진입 번들과 md 청크에는 three와 occt가 없어야 한다).
- 메시 파싱과 STEP tessellation은 ES 모듈 Worker에서 처리한다. Worker가 asset URL을 직접 스트리밍으로 읽는다.
- 공유 코어 `src/three/core/`는 Tauri에 의존하지 않는다. 앱과 내보낸 HTML 런타임이 함께 쓴다.

**Tech Stack:** three(정확한 버전으로 고정), occt-import-js 0.0.23, meshoptimizer, @gltf-transform ^4, three-mesh-bvh, Vite 8 worker(es), Tauri 2 raw IPC

**Spec:** `docs/superpowers/specs/2026-10-26-view-anything-design.md`(3D, 좌표계 프리셋, HTML 내보내기 절). v0.2에 대해 사용자가 내린 결정은 아래 Global Constraints에 있으며 spec보다 우선한다.

## Global Constraints

- **형식:** stl, obj, ply, gltf, glb, step, stp, iges, igs(대소문자 무시). STEP/IGES도 v0.2에 포함한다.
- **100MB 이상 파일**
  - JSON 배열 IPC(`read_file`)로 읽지 않는다. 스트리밍 fetch를 쓰고, 실패하면 `read_file_raw`(raw 바이트)로 대체한다.
  - 진행률을 표시하고, UI 스레드가 멈추지 않아야 한다.
- **시작 속도**
  - 진입 청크와 md viewer 청크는 three와 occt를 정적으로 참조하지 않는다(`scripts/check-bundle.mjs`로 강제).
  - v0.1의 md 시작 속도(약 0.6초)가 회귀하면 안 된다.
- **조작:** Meshmixer 방식이다. 좌드래그는 회전, 우·중드래그는 팬, 휠은 커서 기준 줌이다. 전체 맞춤(F)과 표준 뷰(앞, 뒤, 좌, 우, 위, 아래, 등각)를 둔다.
- **드롭과 열기**
  - 3D 창: 3D 파일은 append, 3D가 아닌 파일은 새 창으로 연다. Shift+드롭이면 3D 파일도 새 창으로 연다.
  - 빈 창: 첫 파일은 그 자리에서 열고, 같은 드롭의 나머지 3D 파일은 append한다.
  - md 창: v0.1 규칙(항상 새 창)을 유지한다.
  - 3D 창의 Ctrl+O도 같은 규칙을 따른다.
- **좌표**
  - 값은 파일 그대로 쓴다. 화면 기본 좌표계는 **Z-up 오른손**이다.
  - 프리셋: Z-up RH(CATIA/NX/Creo/STEP), Y-up RH(glTF/Maya/SolidWorks), ROS REP-103(X 앞, Y 왼쪽, Z 위, 단위 m), Y-up LH(Unity), Z-up LH(Unreal). 단위는 mm, cm, m, inch.
  - 화면 기준 좌표계와 객체별 원본 좌표계·단위를 고를 수 있고, 객체별 기본값은 "그대로"다.
  - **STEP/IGES는 mm로 통일**해서 읽는다(occt `linearUnit: "millimeter"`).
- **장면 패널**
  - 구조는 파일 아래 어셈블리 트리다(STEP 파트 이름과 계층, OBJ의 o/g, glTF 노드).
  - 노드마다 표시/숨김을 두고, 파일 단위로 제거할 수 있다.
  - 큰 트리는 처음에 깊이 1까지만 펼치고, 하위 노드는 펼칠 때 그린다.
- **보조 기능:** 표시 모드(솔리드, 와이어, 솔리드+엣지, X-ray), 치수 정보(객체 bbox 크기, 삼각형 수, 커서 좌표: 화면 좌표와 원본 좌표), X/Y/Z 단면 슬라이더. 거리 측정은 넣지 않고, 단면 캡도 채우지 않는다(비목표).
- **HTML 내보내기**
  - 앱 뷰어와 같은 기능(패널, 트리, 표시 모드, 단면, 표준 뷰, 치수)을 담는다. 파일 제거와 프리셋 편집 기능은 뺀다.
  - 내보낸 시점의 카메라, 표시 여부, 모드로 열린다.
  - 외부 요청이 없는 단일 파일이고, meshopt로 압축하며, 50MB를 넘으면 경고한다.
- **테마:** `--bg/--fg/--muted/--border`와 `data-theme`(light, dark, system)를 재사용하고, 테마가 바뀌면 3D 배경과 그리드도 따라 바뀐다.
- **보안:** CSP는 필요한 만큼만 넓힌다. `script-src 'self' 'wasm-unsafe-eval'`, `connect-src`에 `asset: http://asset.localhost`, `worker-src 'self' blob:`. 기존 md 쪽 보안 장치(sanitize, 링크 차단, UNC 차단)를 약화하지 않는다.
- **커밋:** Conventional Commits 형식에 scope는 붙이지 않는다. 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 단다. main에 커밋하고, push는 컨트롤러가 한다.

## Review Focus

1. 100MB 이상 STL/STEP: 진행률이 움직이는지, 메모리 부족을 안내하는지, Worker를 종료해 메모리를 회수하는지. 메인 스레드가 수백 ms 이상 막히면 안 된다.
2. 파일 제거와 append를 반복해도 GPU와 메모리 리소스가 새지 않아야 한다(geometry, material, BVH, edges dispose).
3. 왼손 프리셋(Unity, Unreal)에서 면이 뒤집혀 보이지 않아야 한다. 단면과 좌표 표시가 화면 좌표계 기준으로 맞아야 한다.
4. 내보낸 HTML이 오프라인에서 열리고, `</script>`가 들어간 파트 이름 같은 입력에도 깨지지 않아야 한다. 파트 이름은 textContent로만 표시한다(XSS 방지).
5. md 창의 동작(드롭하면 새 창, Ctrl+O, 저장 보호)이 회귀하지 않아야 한다.

### Task 1: 기반 — raw IPC, CSP, 포맷 판별, 레지스트리, 번들 가드

**Files:** `src-tauri/src/lib.rs`, `src-tauri/Cargo.toml`(windows-sys), `src-tauri/tauri.conf.json`, `src-tauri/capabilities/default.json`, `src/platform.ts`, `src/registry.ts`, `src/three/formats.ts`(새 파일), `src/three/viewer.ts`(스텁), `src/three/io/source.ts`, `vite.config.ts`, `package.json`, `scripts/check-bundle.mjs`, tests

**Interfaces (Produces):**
- **Rust 명령**
  - `read_file_raw(path) -> tauri::ipc::Response`: 원본 바이트를 그대로 넘긴다.
  - `write_file_raw(request: tauri::ipc::Request)`: 본문은 raw 바이트이고, 경로는 헤더 `x-va-path`에 퍼센트 인코딩해서 받는다. 기존 원자적 쓰기(`write_target`/`write_atomic`)를 재사용한다.
  - `modifier_shift() -> Option<bool>`: Windows는 `GetAsyncKeyState(VK_SHIFT)`를 읽고, 그 밖의 OS는 `None`을 돌려준다.
- **TS (`src/platform.ts`)**
  - `platform.readFileRaw(path): Promise<ArrayBuffer>`
  - `platform.writeFileRaw(path, data: Uint8Array)`
  - `platform.modifierShift(): Promise<boolean | null>`
  - `platform.saveDialog(opts)`
- **TS (`src/three/io/source.ts`)**
  - `fetchWithProgress(url, onProgress(loaded,total), signal): Promise<ArrayBuffer>`: Content-Length 크기로 미리 할당한 버퍼에 스트리밍하고, 실패하면 `readFileRaw`로 대체한다.
- **TS (`src/three/formats.ts`, three를 import하지 않음)**
  - `THREE_D_EXTENSIONS`, `isThreeD(path)`
  - `formatOf(path): "stl"|"obj"|"ply"|"gltf"|"glb"|"step"|"iges"|null`
  - `isBinaryStl(bytes)`: 헤더가 "solid"로 시작하는 바이너리 STL도 크기 공식으로 판별한다.
- **레지스트리:** 3D 확장자를 `() => import("./three/viewer")`로 연결한다. 이 작업에서 viewer는 "3D 뷰어 준비 중" 스텁이다.
- **설정 변경**
  - `pickFiles` 필터에 "3D 모델"을 추가한다.
  - `fileAssociations`에 3D 확장자를 추가한다(name "3D Model", role "Viewer").
  - CSP(csp와 devCsp 둘 다)를 Global Constraints대로 바꾼다.
  - Vite: `worker.format "es"`, `build.target "es2022"`, `build.manifest true`
- **의존성:** `npm view`로 확인한 정확한 버전으로 설치한다. three, @types/three, occt-import-js@0.0.23, meshoptimizer, @gltf-transform/core|extensions|functions, three-mesh-bvh. 이 작업에서는 설치만 하고 코드에서 아직 쓰지 않는다.
- **번들 가드 `scripts/check-bundle.mjs`:** 빌드 manifest를 읽어, 진입 청크와 md viewer 청크의 정적 import 그래프에 three나 occt 청크가 있으면 exit 1로 실패한다. `npm run build` 뒤 CI에서도 돌린다(`ci.yml`에 단계를 추가한다).

**Tests**
- formats: 확장자 대소문자, 경로 구분자, ASCII/바이너리 STL과 "solid" 헤더 바이너리
- registry: 3D 확장자 매핑
- Rust: raw 읽기/쓰기 왕복, 헤더 경로 퍼센트 디코딩, `modifier_shift`가 패닉하지 않는지
- check-bundle: 가짜 manifest fixture로 통과와 실패 경우를 확인

### Task 2: 순수 코어 — 좌표 프레임, 장면 모델, 뷰 계산

**Files:** `src/three/core/frames.ts`, `src/three/core/scene-model.ts`, `src/three/core/views.ts`, tests

**Interfaces (Produces):**
- **`frames.ts`** (three에 의존하지 않고 number[] 행렬만 다룬다)
  - `type FramePreset = "zup-rh"|"yup-rh"|"ros"|"yup-lh"|"zup-lh"`, `type Unit = "mm"|"cm"|"m"|"in"`, `UNIT_MM`
  - `basis(p): number[9]`: 프리셋 좌표를 기준 프레임 C(Z-up RH)로 보내는 행렬
  - `displayRootMatrix(display): number[16]` = `B_yup⁻¹·B_display`(three의 world는 Y-up)
  - `objectMatrix(display, displayUnit, source|"as-is", sourceUnit|"as-is"): number[16]` = `B_D⁻¹·B_S·(u_S/u_D)`. 둘 다 "as-is"면 단위 행렬이다.
  - `toDisplay`/`toSource`(점 변환)
- **`scene-model.ts`**
  - `SceneFile {id, path, name, format, sourceFrame, sourceUnit, root: TreeNode}`
  - `TreeNode {id, name, kind: "file"|"assembly"|"part"|"mesh", visible, children, meshIds, stats?}`
  - `buildTree(parsed: ParsedTree, fileName)`: 이름 없는 단일 루트는 파일 노드로 합친다. 빈 이름은 메시 이름, 그것도 없으면 `Part N`으로 채운다.
  - `setVisible(model, nodeId, v)`, `removeFile`, `findNode`
- **`views.ts`**
  - `fitDistance(radius, fovDeg, aspect)`
  - `standardViewDirection(name, displayFrame)`: 화면 좌표계 기준 방향 벡터

**Tests (정확한 값)**
- `det(basis(p))`는 RH 프리셋이 +1, LH 프리셋이 -1
- 기본 화면 Z-up일 때 displayRoot가 (0,0,1)을 three world (0,1,0)으로 보냄
- inch→mm 배율 25.4, objectMatrix의 왕복 변환이 단위 행렬
- occt 형태 fixture로 트리 생성, 루트 합치기, `Part N` 이름 채우기
- 표시/숨김 설정, 파일 제거
- fitDistance가 단조 증가

**Commit:** `feat: add coordinate frames, scene model and view math`

### Task 3: 스테이지와 메시 형식

**Files:** `src/three/core/stage.ts`, `src/three/core/build-objects.ts`, `src/three/core/three.css`, `src/three/worker/protocol.ts`, `src/three/worker/parse.worker.ts`, `src/three/viewer.ts`, `tests/fixtures/3d/*`(작은 stl/obj/ply/glb), tests

**Requirements**
- **stage**
  - WebGLRenderer(antialias)에 PerspectiveCamera와 OrbitControls를 붙인다. 버튼 매핑은 LEFT=회전, MIDDLE=팬, RIGHT=팬이고 `zoomToCursor`를 켠다.
  - near/far는 바운딩 구에서 계산한다.
  - 조명은 HemisphereLight와 DirectionalLight를 카메라에 붙여서 쓴다.
  - 그리드와 축은 화면 좌표계 기준으로 그린다(기본 Z-up).
  - 변경이 있을 때만 다시 그린다(requestRender).
  - `data-theme` MutationObserver와 matchMedia로 배경과 그리드 색을 바꾼다.
  - resize는 ResizeObserver로 처리한다.
  - WebGL2를 쓸 수 없으면 안내 메시지를 띄운다.
- **Worker** (`new Worker(new URL(...), {type:"module"})`)
  - 입력은 `{id, url, format}`이다. Worker가 직접 `fetchWithProgress`로 읽고 `progress{phase:"read"|"parse", loaded,total}`를 보낸다.
  - STL/OBJ/PLY는 three 로더의 `.parse`로 처리하고 `ParsedFile{tree, meshes:[{name, positions, normals?, indices?, colors?}]}`를 transfer로 넘긴다.
  - OBJ는 o/g를 트리 노드로 만든다.
- **glTF/GLB:** 메인 스레드에서 `fetchWithProgress` 후 `GLTFLoader.parseAsync`로 읽는다. 외부 .bin과 텍스처는 LoadingManager의 `setURLModifier`로 형제 경로를 assetUrl로 바꿔 찾는다. 노드 트리를 만든다.
- **build-objects:** ParsedFile을 Group으로 만들고 `nodeId → Object3D` 맵을 만든다. 기본 재질은 MeshStandardMaterial이고, vertex color가 있으면 쓴다.
- **viewer.ts**
  - mount하면 화면 전체 캔버스, 진행률 오버레이(파일명, 단계, %), 파일 하나 로드 후 fit-all을 처리한다.
  - 키 F는 전체 맞춤이고, 1~7은 표준 뷰다. 툴바 버튼도 둔다.
  - 오류는 배너로 보여 준다.
- **Tests:** 작은 fixture로 Worker 파싱 함수(Worker 밖에서 직접 호출할 수 있게 분리)를 node에서 실행해 정점 수와 트리를 확인한다. 진행률 계산도 테스트한다.

**Commit:** `feat: render stl, obj, ply and gltf in a 3d stage`

### Task 4: STEP/IGES (occt)

**Files:** `src/three/worker/occt.ts`, `parse.worker.ts`, `tests/fixtures/3d/cube.step`(+ 2파트 어셈블리 step), tests

**Requirements**
- **occt 로드**
  - occt-import-js를 Worker 안에서 동적 import한다. wasm은 `?url` + `locateFile`로 찾는다.
  - `ReadStepFile`/`ReadIgesFile`에 `{linearUnit:"millimeter", linearDeflectionType:"bounding_box_ratio", linearDeflection, angularDeflection}`을 넘긴다. 정밀도는 파일 크기에 따라 단계적으로 바꾼다(작은 파일은 정밀, 큰 파일은 거칠게).
- **결과 매핑:** occt 결과(root 트리, meshes, brep_faces 색)를 ParsedFile로 바꾼다. 면 색은 vertex color로 옮긴다.
- **진행 단계:** read → tessellate. tessellate 단계는 % 없이 스피너로 표시한다.
- **메모리:** 파일을 처리한 뒤 Worker를 종료한다(wasm 메모리 회수). abort나 OOM이 나면 "파일이 너무 크거나 손상됨. 정밀도를 낮춰 다시 시도" 버튼을 띄우고, 누르면 deflection을 높여 다시 시도한다.
- **Tests:** node에서 cube.step을 파싱해 트리와 삼각형 수가 0보다 큰지, 단위가 mm인지 확인한다(inch로 작성한 fixture가 있으면 mm 값인지도). 어셈블리 이름과 계층도 확인한다.

**Commit:** `feat: open step and iges through occt in a worker`

### Task 6: 좌표계 프리셋 UI

### Task 8: HTML 내보내기

**Files:** `vite.runtime.config.ts`, `src/three/export-runtime/main.ts`, `src/three/export/export-html.ts`, `src/three/export/template.ts`, `package.json`(`build:runtime`을 `build` 앞과 `predev`에서 실행), tests

- **내보내기 흐름**(`export-html.ts`, lazy, 런타임은 `?raw`로 가져옴)
  1. 보이는 장면을 GLTFExporter로 GLB로 만든다. 프리셋 행렬을 노드에 반영하고, `extras.vaId`로 노드 id를 유지한다.
  2. @gltf-transform으로 `quantize()`와 `meshopt()`를 적용한다.
  3. base64로 바꿔 `<script type="application/octet-stream" id="va-glb">`에 넣는다.
  4. 상태 JSON(카메라, 화면 좌표계와 단위, 모드, 단면, 표시 여부, 트리 이름)을 넣는다.

  6. 메타 CSP는 `default-src 'none'; script-src 'unsafe-inline' 'wasm-unsafe-eval'; style-src 'unsafe-inline'; img-src data: blob:`로 한다.
- **저장:** `save()` 대화상자(기본 이름 `<첫 파일>.html`)에서 경로를 받고 `writeFileRaw`로 쓴다. 50MB를 넘으면 확인 대화상자를 띄운다. 처리 중에는 처리 중 표시를 보여 준다.

- **Tests:** template의 이스케이프(`</script>`가 든 이름), base64 왕복, 50MB 경계, 상태 JSON 스키마. 런타임 번들이 `@tauri-apps`를 참조하지 않는지 grep 테스트도 둔다.

**Commit:** `feat: export the 3d scene as a single offline html`
